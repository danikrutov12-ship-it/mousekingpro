## «Убрать текст с видео» — выпущено в 2.2.0

Цель владельца: в режиме «Видео» отправить ролик до 10 минут, выделить мышкой текст, логотип или субтитры
и получить видео без них. Обработка идёт на своём RunPod через video-subtitle-remover. Нужны все четыре
алгоритма: STTN, STTN с поиском текста, LAMA, ProPainter. Устройство описано в [RUNPOD.md](RUNPOD.md), раздел «Убрать текст с видео».

**Готово и проверено:**
- модель в списке «Видео», панель с алгоритмами, предупреждения;
- редактор рамок поверх кадра с ползунком, проверен снимками в тестовом режиме: рамки ложатся точно;
- лимит 10 минут при отправке;
- S3-ключ в настройках с проверкой при сохранении (владелец сохранил ключ, проверка прошла — S3 работает);
- проверка типов и сборка проходят;
- **воркер на RunPod работает** (18.11.2026): все четыре алгоритма проверены на эндпоинте `mouse-king-vsr`
  тестовым роликом 1280×720, 8 с. Результат — H.264 + AAC, звук сохраняется, текст убран чисто:

  | Алгоритм | Рамка | Работа на 8 с видео | Примерно за минуту видео 720p |
  |---|---|---|---|
  | STTN (`sttn-auto`) | да | 19 с | ~1–2 мин GPU, ~$0.02–0.04 |
  | STTN + поиск (`sttn-det`) | нет, нашёл сам | 27 с | ~3 мин, ~$0.06 |
  | LAMA | нет, нашёл сам | 40 с | ~5 мин, ~$0.09 |
  | ProPainter | да | 64 с | ~8 мин, ~$0.15 |

  Холодный старт (первый воркер после простоя) — около 2 минут. Цены — оценка по времени на RTX 4090,
  точные цифры видны в Настройки → RunPod → расходы.

**Проверка владельцем (18.11.2026) и исправление:** на вертикальном ролике 576×1024 с подписью на белой плашке
посередине все алгоритмы работали плохо: ProPainter давал чёрный прямоугольник, STTN — белое пятно. Причина — в VSR:
полоса вокруг надписи, внутри которой идёт закраска, имеет высоту «ширина × 3/16» (108 px при подписи ~100 px),
фона в ней почти нет. `job.py` (`patch_vsr`) при каждой задаче правит файлы VSR в контейнере на
«max(ширина × 3/16, высота / 4)» — горизонтальные видео не меняются. После этого ProPainter убрал подпись чисто.
STTN и LAMA на таком видео всё равно слабые (плашка стоит весь ролик, фона за ней не видно; LAMA и sttn-det
стирают только буквы) — подсказки к алгоритмам в программе это объясняют и советуют ProPainter.

**Проверено владельцем в программе:** весь путь прикрепить видео → рамка → отправить → видео в чате и галерее,
с сохранённым S3-ключом (ролик 1 МБ: загрузка на диск одним запросом и скачивание по S3 работают).

**Не проверено:**
1. Загрузка большого видео по частям (`main/s3.ts`, части по 32 МБ — multipart), например 300 МБ и 9 минут.
2. Видео 1080p и 4K с ProPainter: обработчик уменьшает число кадров в памяти под видеокарту (`set_config`
   в `worker/vsr/job.py`); на 24 ГБ при 4K возможна нехватка памяти.

Если что-то сломается на первых настоящих роликах — смотрите сначала эти пункты.

**Возможное улучшение (владелец пока не решил):** сделать ProPainter алгоритмом по умолчанию — для подписей на
плашке (TikTok) он единственный работает хорошо, но дороже STTN в 3–4 раза.

**Почему воркер раньше не работал (для истории):** `start.sh` ставил пакет `runpod` прямо на сетевой диск —
около 2 минут. Всё это время воркер не брал задачи, RunPod гасил его как простаивающего (`idleTimeout 20`),
установка не доходила до конца, и следующий воркер начинал её заново. Теперь пакет ставится в локальную папку
контейнера (секунды) и в фоне копируется на диск; на диске он уже лежит (`/runpod-volume/vsr/pylib`).
Нашли через обычный GPU-под с тем же образом, отдающий лог по HTTP (`ports: 8000/http`, адрес
`https://<id пода>-8000.proxy.runpod.net/`), — у serverless-воркеров логи через API недоступны.

**Эндпоинты:** все алгоритмы, включая ProPainter, идут на `mouse-king-vsr` (`workersMax 3`). Обработчик подбирает
память ProPainter под видеокарту, поэтому карты 24–48 ГБ подходят. Эндпоинт `mouse-king-vsr-hq` (только 48 ГБ+)
не используется: в EU-RO-1 таких карт часто нет, задачи висели «throttled». Он на паузе (`workersMax 0`),
его можно удалить.

**REST API RunPod (`rest.runpod.io`) 18.11.2026 пропал из DNS целиком.** Поиск эндпоинтов и дисков в программе
переведён на GraphQL (`account()` в `main/runpod.ts`). На REST остались: расходы
(`spend()` — «Не удалось получить расходы RunPod», пока REST лежит) и описание в RUNPOD.md. Скрипты
`worker/vsr/tools/*.sh` работают через GraphQL. Менять `workersMax` без REST — GraphQL `saveEndpoint`
(нужны все поля: `id, name, gpuIds, templateId, networkVolumeId, idleTimeout, scalerType, scalerValue,
workersMin, workersMax, executionTimeoutMs`; текущие значения — `query { myself { endpoints { ... } } }`).

## Небольшие хвосты

- **Остатки фейсвапа.** Теги `worker-v1` и `worker-v2` в репозитории и, возможно, образ воркера в GitHub Packages
  (GHCR). Код и RunPod уже очищены. Удалять теги и пакет только с согласия владельца.
- **Диск RunPod на 200 ГБ** стоит около $14 в месяц, это главный постоянный расход. Владельцу предлагали
  перенести модели на диск 150 ГБ без bf16-файла Qwen Edit (около $10.5 в месяц, теряется «Макс. качество»).
  Решения пока нет.
- **WaveSpeed** (Qwen Image 3 Pro) встроен в 2.1.6. Проверки на реальном ключе владельца в истории нет:
  если владелец сообщит об ошибке, первым делом смотрите `main/wavespeed.ts`.
