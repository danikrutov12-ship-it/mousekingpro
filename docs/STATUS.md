## В работе: «Убрать текст с видео» (ветка `vsr`)

Цель владельца: в режиме «Видео» отправить ролик до 10 минут, выделить мышкой текст, логотип или субтитры
и получить видео без них. Обработка идёт на своём RunPod через video-subtitle-remover. Нужны все четыре
алгоритма: STTN, STTN с поиском текста, LAMA, ProPainter. Устройство описано в [RUNPOD.md](RUNPOD.md), раздел «Убрать текст с видео».

**Готово и проверено:**
- модель в списке «Видео», панель с алгоритмами, предупреждения;
- редактор рамок поверх кадра с ползунком, проверен снимками в тестовом режиме: рамки ложатся точно;
- лимит 10 минут при отправке;
- S3-ключ в настройках с проверкой при сохранении;
- загрузка и скачивание по S3 с подписью SigV4 (без AWS SDK, большие файлы по частям);
- проверка типов и сборка проходят;
- на RunPod созданы шаблон `mkp-vsr` и эндпоинты `mouse-king-vsr` и `mouse-king-vsr-hq`,
  обработчик выложен на диск в `/runpod-volume/vsr/`.

**Не проверено:** S3 на настоящем ключе (его ещё не создавали), обработка видео целиком — до обработки дело не дошло.

**Блокер:** воркеры с образом `eritpchy/video-subtitle-remover:1.4.0-cuda12.8` в статусе «running» живут несколько
секунд (один раз около 1.5 минуты) и гаснут. Задача остаётся в очереди. Запасной `diag.py` тоже ничего не вернул,
значит, контейнер падает раньше `start.sh` или в самом его начале. Логи через API RunPod недоступны.
Чтобы не тратить деньги, у обоих VSR-эндпоинтов сейчас **`workersMax = 0`**. Перед тестом верните 3
(`PATCH https://rest.runpod.io/v1/endpoints/<id>` с `{"workersMax":3}`) и после теста снова поставьте 0.

**Следующие шаги:**
1. **Получить лог запуска воркера.** Варианты:
   - веб-панель runpod.io → Serverless → `mouse-king-vsr` → Workers / Logs (может только владелец);
   - создать S3-ключ (владелец согласен, файл `~/.runpod-s3`), дописать в `start.sh` копию лога
     в `/runpod-volume/vsr/logs/` и прочитать его по S3.
2. **Проверить гипотезы** (от самой вероятной):
   - **Не хватает диска контейнера.** Сжатый образ весит 7.3 ГБ, распакованный заметно больше, а у шаблона
     `containerDiskInGb 30`. Поднять до 50–60.
   - **Не применяется `dockerStartCmd` шаблона.** Тогда запускается CMD образа `python /vsr/backend/main.py`
     без `-i` и сразу выходит, что совпадает с картиной «гаснет за секунды». Решение — свой образ
     `FROM eritpchy/video-subtitle-remover:1.4.0-cuda12.8` с `RUN pip install runpod` и
     `CMD ["bash", "/runpod-volume/vsr/start.sh"]`, сборка в GitHub Actions в GHCR (публичный пакет)
     по тегу `vsr-worker-v*`.
   - **Несовместимость CUDA 12.8 образа с драйвером на машине.** Попробовать тег `1.4.0-cuda12.6`
     и убрать RTX 5090 из списка.
3. Когда воркер возьмёт задачу: прогнать `worker/vsr/tools/test.sh` на `test2.mp4` из репозитория VSR
   (1280×720, 8 с, надпись внизу по центру, рамка `[[0.3,0.88,0.7,0.98]]`) во всех четырёх режимах.
   Записать время и стоимость минуты видео, проверить, что звук сохраняется.
4. Проверить загрузку большого видео по S3 (например, 300 МБ и 9 минут) и ProPainter на `mouse-king-vsr-hq`.
5. Пройти весь путь в программе: прикрепить видео, нарисовать рамку, отправить, видео появляется в чате и галерее.
6. Слить `vsr` в `main`. Выпуск — только после слова владельца «выпускай».

## Небольшие хвосты

- **Остатки фейсвапа.** Теги `worker-v1` и `worker-v2` в репозитории и, возможно, образ воркера в GitHub Packages
  (GHCR). Код и RunPod уже очищены. Удалять теги и пакет только с согласия владельца.
- **Диск RunPod на 200 ГБ** стоит около $14 в месяц, это главный постоянный расход. Владельцу предлагали
  перенести модели на диск 150 ГБ без bf16-файла Qwen Edit (около $10.5 в месяц, теряется «Макс. качество»).
  Решения пока нет.
- **WaveSpeed** (Qwen Image 3 Pro) встроен в 2.1.6. Проверки на реальном ключе владельца в истории нет:
  если владелец сообщит об ошибке, первым делом смотрите `main/wavespeed.ts`.
